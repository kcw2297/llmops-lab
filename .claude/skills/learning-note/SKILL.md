# learning-note

## 절차
1. `artifacts/learning/concepts/`에서 같은 개념 노트가 있는지 먼저 확인한다. 있으면 새로 쓰지 않고 내용을 보강한다.
2. 개념 하나당 노트 하나를 쓴다. 실험 노트(06)는 이번에 다룬 개념들의 요약과 링크로 구성한다.
3. 실험에서 나온 **실제 수치를 반드시 인용**한다. 예: "L4에서 max-model-len 8192일 때 GPU blocks 2,345개".
4. roadmap에 개념 체크 표시를 한다.

## 개념 노트 형식 (`concepts/{kebab-name}.md`)
```
# {개념}
## 한 줄 정의
## 백엔드/DevOps로 치면
## 실제로는 어떻게 동작하나 (그림 또는 의사코드, 필요하면 수식 1개)
## 내 실험에서 본 것  (실험 링크 + 수치)
## 흔한 오해
## 더 파볼 것  (공식 문서나 논문 1~2개)
## 자가 점검 퀴즈  (3문항, 답은 <details>로 숨김)
```

## 실험 노트 형식 (`06-learning-note.md`)
```
# 이번 실험에서 배운 것
- 가설은 맞았나? 틀렸다면 왜?
- 새로 배운 개념: [[...]]
- 가장 의외였던 점:
- 아직 모르겠는 것 (다음에 물어볼 것):
```

## 품질 체크
- 비유가 개념을 왜곡하지 않는가? 비유가 맞지 않는 부분은 "비유의 한계"로 함께 적는다.
- 사용자가 아직 모르는 용어를 설명 없이 쓰지 않았는가?
