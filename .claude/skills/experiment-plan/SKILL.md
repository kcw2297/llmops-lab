# experiment-plan

## 절차
1. roadmap에서 이번 실험이 어느 마일스톤에 해당하는지 적는다.
2. **질문 하나**로 목표를 정한다. 예: "L4 1장에서 8B bf16 모델의 동시 16 요청 처리량은?"
3. 가설을 쓴다. 예상 수치와 그렇게 예상한 이유를 함께 적는다. 틀려도 되며, 틀린 가설이 학습 포인트가 된다.
4. 모델 후보를 고른다. 라이선스, gated 여부, tool calling 지원 여부를 확인한다.
5. VRAM을 계산한다 (`model-serving`의 계산식 사용).
6. 성공 기준은 측정 가능한 수치로 쓴다.
7. 예상 GPU 사용 시간을 적는다. 비용은 infra-engineer가 계산한다.
8. 범위 밖 항목(이번에 안 하는 것)을 적는다.

## 출력 형식 (`01-plan.md`)
```
# {제목}
- 마일스톤: M{n}
- 질문:
- 가설: (예상 수치 + 이유)
- 모델: {repo}@{revision}, 라이선스, gated 여부
- VRAM 계산: 가중치 {x}GB + KV {y}GB + 여유 {z}GB = {total}GB
- 사용 config: `{module}/configs/*.yaml` (새 실험은 config 추가로 만든다), 레시피 git 커밋: `{sha}`
- 실험 변수 / 고정 조건:
- 성공 기준:
- 예상 GPU 시간:
- 범위 밖:
- 이번에 배울 개념 후보: (2~4개)
```

## 품질 체크
- 성공 기준이 숫자인가?
- 한 실험에서 바꾸는 변수가 1~2개 이하인가? 너무 많으면 실험을 나눈다.
- 정보가 부족하면 추측하지 말고 `확인 필요:`로 표시한다.
