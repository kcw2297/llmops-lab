# vat-slip-v1 — 가상 부가가치세 납부서 (합성)

| 항목 | 값 |
|---|---|
| 용도 | M1 스모크(`20261120-m1-qwen3vl-8b-vllm`): VLM 문서 → JSON 추출이 되는지, 이미지 토큰 수, JSON 유효율, 필드 정답률 참고값 |
| 건수 / 양식 | 8장 / 1종(가상 부가가치세 납부서, 레이아웃 고정, 값만 다름) |
| 이미지 | PNG, A4 150dpi, 1240×1754, RGB, 한국어 인쇄체(Apple SD Gothic Neo), 노이즈·회전·스캔 열화 없음 |
| 예상 이미지 토큰 | 32×32px당 1개 → 39×55 = **2,145** (Qwen3-VL / Qwen3.5, 픽셀 상한 안쪽일 때) |
| 정답 | `labels/{doc_id}.json`, `schema.json`(JSON Schema 2020-12)으로 검증됨 |
| 라이선스 | 자체 합성. **실데이터 아님** |
| 생성 | `eval/src/ocr_eval/synth/vat_slip.py`, seed `20261120` |

## 🔴 실데이터 아님
이 레포는 Public이다. 모든 값은 가짜다.
- 상호: 가나다 순 음절로 만든 이름(가나다상사, (주)라마바테크 …). 세무서·은행도 가상(가람/나래/다온/라온세무서, 가나/다라/마바은행).
- 사업자등록번호: 형식(3-2-5)만 맞추고 앞 3자리 `000`(없는 세무서 코드) + **체크섬을 일부러 틀리게** 생성.
- 전자납부번호(19자리, 4-4-1-10 표기)·가상계좌(`000-xxxx-xxxx-xx`): `0000`/`000`으로 시작하는 난수.
- 이미지 상단과 하단에 "합성 견본 · 평가용 (실제 서류 아님)", "synthetic"이 인쇄돼 있다.

## 재생성
```bash
uv run python -m ocr_eval.synth.vat_slip --out eval/datasets/vat-slip-v1
```
- 같은 seed면 `labels/`와 `schema.json`은 항상 같다.
- PNG 바이트는 Pillow 버전(생성 시 13.0.0)과 macOS 폰트 파일이 같을 때 같다. `manifest.json`의 sha256과 비교한다. 다른 환경에서 이미지가 달라졌으면 덮어쓰지 말고 v2로 올린다.
- 데이터셋을 바꾸면(필드, 레이아웃, 건수) **버전을 올린다**(v1 → v2). v1을 덮어쓰면 과거 실험과 비교할 수 없다.

## 필드 (schema.json)
| 필드 | 타입(`x-ocr-type`) | 문서 위치 | 정규화(채점) |
|---|---|---|---|
| `taxpayer_name` | text | 납부자 상호 | 공백 정리만. `(주)`·괄호는 그대로 비교 |
| `business_reg_no` | id | 사업자등록번호 | 숫자·영문만 남김(하이픈·공백 무시) |
| `tax_item` | text | 세목 | 항상 "부가가치세" |
| `tax_period_start` | date | 과세기간 앞 | `YYYY-MM-DD` |
| `tax_period_end` | date | 과세기간 뒤 | `YYYY-MM-DD` |
| `due_date` | date | 납부기한 | `YYYY-MM-DD` |
| `total_amount` | amount | 납부할 세액 표의 **합계** 행 | 정수(원). 콤마·"원" 제거 |
| `electronic_payment_no` | id | 전자납부번호 | 숫자만 |
| `virtual_account_no` | id | 납부계좌(가상계좌), 은행명 제외 | 숫자만. 없으면 `null` |
| `tax_office` | text | 관할세무서 | 공백 정리 |

- 공통 null: `None`, `""`, `"null"`, `"-"`, `"없음"`, `"해당 없음"`, `"N/A"`는 모두 null로 본다.
- `x-ocr-type`은 채점기 전용 메타데이터다. 서버로 보낼 때 `strip_meta()`가 제거한다.
- 필드명은 앱(`ocr-agent`) 2단계 기획서 3절(납부 총액, 세목, 과세기간, 납부기한, 납부 계좌)과 M1 plan 필드 예시를 합친 것이다. 앱 `ocr` 모듈 스키마가 생기면 이 이름을 그대로 쓰도록 맞춘다.

- 방해 요소: 발행일(정답 아님), 본세·가산세 행(003, 006은 가산세 0이 아니어서 본세 ≠ 합계), 하단 "○○세무서장". 모델은 **합계 행을 읽어야** 하고 본세+가산세를 계산하면 안 된다.
- 과세기간: 1기 예정(01-01~03-31), 1기 확정(01-01~06-30), 2기 예정(07-01~09-30), 2기 확정(07-01~12-31). 납부기한은 종료 다음 달 25일.
